# 0005 — Pins: 8 pins, clock source forced internal, 4 post-boot GPIOs

- **Status**: proposed — flips to `RATIFIED` in this PR after the two
  independent reviews (engineering and market) required by the repo
  instructions.
- **Supersedes**: the README draft row "GPIO: 6 pins, each input or output".
- **Superseded by**: none.
- **Spec rows**: `spec/target-spec.md` rows 4, 11 (Clock, Pin count & mux),
  § Pin mux.

## Context

The draft keeps "Pin count: 8" and "GPIO: 6 pins". An 8-pin package carries
supply and ground, so at most **6 signal pins** exist, and the draft's own
other rows spend them: program storage = external SPI flash (4 signals,
record 0003) and one UART (2 signals, record 0004) already total 6. A clock
input — which the draft's "≥ 16 MHz system clock" implies — has no pin left
to live on. The draft's 6-GPIO row is arithmetically impossible together
with its own program-storage row; this record is where that contradiction is
resolved, not papered over.

## Decision

1. **Pin assignment (sums to 8, supply included):**

   | Pin | Signal | Function(s) |
   |---|---|---|
   | 1 | `VDD` | 1.8 V core supply (record 0001) |
   | 2 | `GND` | ground |
   | 3 | `flash_sclk` / `gpio0` | boot+reprogram clock during boot / GPIO after release |
   | 4 | `flash_cs_n` / `gpio1` | boot chip-select / GPIO after release |
   | 5 | `flash_copi` / `gpio2` | boot data out / GPIO after release |
   | 6 | `flash_cipo` / `gpio3` | boot data in / GPIO after release |
   | 7 | `uart_rx` | console input; **reset strap** (low at reset exit ⇒ UART boot, record 0003) |
   | 8 | `uart_tx` | console output |

2. **GPIO count: 4** (pins 3–6, muxed with the flash signals, released by
   the boot FSM at boot end — record 0003). The draft's 6-GPIO row is
   dropped for the arithmetic above, with the flash-share making the pins
   useful both before and after boot.
3. **Clock source: internal ring oscillator** — the pin budget leaves no
   room for an external clock input, so the system clock is an on-chip
   inverter ring in RTL (a handful of gates, charged to the AREA row).
   Target **≥ 16 MHz at `tt_025C_1v80`**; the ring length is an RTL choice
   that the recorded ngspice measurement fixes. The uncalibrated variance
   of a ring oscillator is real: the UART accommodates it by
   software auto-baud (record 0004) and the UART-boot loader by hardware
   auto-baud (record 0003); no frequency-accuracy claim is made here.
4. **Clock fallback: external clock applied on `gpio0`** after boot, via a
   two-gate clock mux selected by software. This costs one GPIO when used
   and exists for lab bring-up and for applications that have a clock to
   spare. It is the only external-clock path.
5. **Programming and debug share pins, as the issue asks**: programming =
   UART boot (pin 7) or software bit-banged flash reprogram on pins 3–6
   (record 0003); debug = the UART console (pins 7–8). No dedicated
   programming or debug pins exist.
6. **Reset: on-chip, all-digital.** No reset pin exists — Decision 1's
   arithmetic spends all 8 — and the pinned PDK ships no POR cell: the
   `sky130_fd_sc_hd` and `sky130_fd_sc_hvl` cell lists contain no
   POR/power-on cell (checked in the `libs.ref` cell lists of record
   0002's PDK pin, 2026-11-19), and an analog power-on detector is out of
   charter (digital block, no analog half). Reset is therefore generated
   from standard cells: the ring oscillator of Decision 3 clocks a release
   counter that holds `reset_n` asserted for **256 ROSC cycles**
   (≥ 16 µs at the 16 MHz target) after power is applied, then releases
   the boot FSM and the core together (reset exit). **The `uart_rx` strap
   (Decision 1, record 0003) is sampled once, on the system-clock edge at
   counter terminal count**, through a 2-FF synchronizer that has the
   whole count to settle. The count covers ROSC start-up and synchronizer
   settling; it is **not** a supply-ramp guarantee — no power-ramp behavior
   is specified. Verified by the cocotb reset testbench (strap sample
   instant, release order, counter behavior).

## Alternatives considered

- **6 GPIO (draft).** Dropped: impossible with external program storage and
  a UART on 8 pins — shown by the signal-pin arithmetic above.
- **External clock pin (draft implies one).** Dropped: it would force
  dropping either the UART (losing the only programming/debug surface) or
  two flash pins (losing persistent program storage). The internal ring +
  auto-baud is the coherent package; the gpio0 fallback keeps an external
  clock reachable for the lab.
- **Single-wire UART (share rx/tx on one pin) to free a 5th GPIO.**
  Rejected: half-duplex console complicates the boot loader and the
  firmware for one GPIO; not worth it for the target.
- **XIP flash to keep the pins "always flash".** Rejected in record 0003;
  it would strand GPIO = 0.

## Consequences

- The clock row of `spec/target-spec.md` inherits its ≥ 16 MHz number and
  its verification from this record; the ROSC's measured frequency and
  variance land in the verification records, never in a spec promise
  beyond the target.
- `uart_rx` is a strap input at reset — a pin with three duties (strap,
  console RX, auto-baud probe). The cocotb mux testbench owns its truth
  table.
- The 4 GPIO bits bound the "useful" claim of the block: 4 GPIOs + UART is
  the honest deliverable of an 8-pin, external-flash part; anything more
  needs more pins, which is a package change, not a row edit.

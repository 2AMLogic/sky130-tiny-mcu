# 0005 — Pins: 8 pins, clock source forced internal, 4 post-boot GPIOs

- **Status**: proposed — flips to `RATIFIED` in this PR after the two
  independent reviews (engineering and market) required by the repo
  instructions.
- **Supersedes**: the README draft row "GPIO: 6 pins, each input or output".
- **Superseded by**: none.
- **Spec rows**: `spec/target-spec.md` rows 4, 11 (Clock, Pin count & mux),
  § Pin mux.

## Context

An eight-pin package leaves six signals after power and ground. SPI needs
four wires during boot. A digital counter has no defined power-up state,
so the board supplies reset on pin 8. UART TX can share SPI's data input
on pin 5 because the flash ignores DI while deselected. This permits
full-duplex UART after boot and preserves an independent RX boot strap.

## Decision

1. **Package assignment**

   | Pin | Signal | Boot and runtime use |
   |---|---|---|
   | 1 | `VDD` | Nominal 1.8 V core and I/O |
   | 2 | `GND` | Common ground |
   | 3 | `flash_sclk` / `gpio0` / `ext_clk` | SPI clock, then GPIO or external-clock input |
   | 4 | `flash_cs_n` / `gpio1` | Active-low select with external pull-up |
   | 5 | `flash_copi` / `gpio2` / `uart_tx` | SPI DI during the copy, then GPIO or console output |
   | 6 | `flash_cipo` / `gpio3` | SPI DO during the copy, then GPIO subject to flash output-disable time |
   | 7 | `uart_rx` | Strap, UART load and console input. Pull high for normal boot. |
   | 8 | `reset_n` | Active-low input from a board supervisor or the enclosing system |

2. **GPIO with flash attached.** After either load, CS# is high, the GPIO
   output enables and pin-function selects are clear, and the board pull-up
   keeps flash deselected. Hold pin 4 high (or input with pull-up) during
   ordinary GPIO or console use. After the flash's 7 ns maximum output-disable
   time, pins 3, 5 and 6 can be independent GPIO. Selecting UART TX consumes
   pin 5, leaving two. With the flash electrically isolated all four pins
   can be GPIO. For deliberate bit-banged flash access, disable UART TX,
   stop any external drive on the shared lines, set SCLK low and disable
   pin 6 output **before** pulling CS# low. Keep CIPO input until CS# has
   risen and the output-disable time has elapsed. Board peripherals must
   also release these wires throughout boot and flash access.
3. **Internal oscillator.** Instantiate an odd inverter ring from named
   sky130 cells with a buffered clock tap. Preserve the cells, nets and
   feedback (`keep`/`dont_touch`) in synthesis and P&R. Check the routed
   netlist for the closed loop, stage count and load. For STA, disable one
   feedback timing arc in the timing model only and use `create_clock` at the
   buffered ring output as the STA clock source. For zero-delay RTL simulation use a behavioral
   clock. For physical characterization use extracted parasitics and ngspice
   startup and steady-state transients at TT 25 °C/1.80 V, SS 100 °C/1.60 V
   and FF −40 °C/1.95 V, including supported load, ramp and variation cases.
   Record start time, shortest and longest settled periods and high/low
   pulse widths per corner. Require ≥16 MHz nominal at TT. At each corner
   constrain the logic to that corner's shortest supported period with
   documented uncertainty for jitter and ring/logic mismatch. Require
   setup, hold and minimum-pulse checks to pass. Publish supported bounds
   only after characterization. Corner spread alone gives no statistical
   distribution.
4. **External clock fallback.** Boot always uses the ring. With CS# high,
   configure pin 3 as input before enabling the external source, then
   select it via a glitch-free clock mux (0004). Verify handoff with both
   clocks running over relative phase, and at the shortest supported
   external period. Switching back to the ring precedes disconnecting the
   external source. External-clock mode consumes one more GPIO in each count
   above.
5. **Programming and debug.** Use SPI copy or the RX loader to boot, and
   the RX/TX console for debug. Runtime flash programming uses GPIO under
   the ownership rules above. For boot after an MCU-only reset, firmware
   keeps the flash awake in standard SPI mode and uses ordinary,
   unsuspended program/erase operations. Pin 8 resets the MCU alone.
   The SPI loader checks flash BUSY after strap sample on every reset
   (0003). The console receiver on pin 5 must tolerate
   flash boot traffic until firmware selects TX.
6. **Cold start.** The board asserts `reset_n` low from power-up, holds it
   until the MCU rail and ring are stable and the flash rail has been valid
   for at least 20 µs, and reasserts it on loss of valid supply. Specify
   supervisor threshold, delay and tolerances against the chosen board.
   Reset asynchronously clears the release synchronizer, counter,
   boot-done latch, loader state/address and GPIO enables. It forces CS#
   inactive, SCLK low, and disables all RAM writes and core fetches. The
   ring is free-running during reset. Deassertion passes through two ROSC
   flip-flops. Starting on the next rising edge, count **256** rising edges.
   On edge 256 sample the two-flop-synchronized RX strap once and start the
   selected loader. Only its completion releases SERV (0003). Delay is
   specified in cycles. No on-chip brown-out threshold is implied.

## Alternatives considered

- A ring-clocked counter by itself can power up at its terminal count.
  Exposing reset on pin 8 supplies asynchronous assertion even before the
  first clock edge and avoids adding an analog POR to the digital block.
- Six independent GPIOs would spend all six signal pins. Keeping UART TX
  on a dedicated pin in addition to reset and RX would also displace one
  of the four boot wires. The post-boot mux uses a time when DI is idle.
- Fetching directly from flash would keep the shared pins occupied on
  every instruction fetch (0003).

## Consequences

The integration bench must start from unknown or randomized flop values,
apply actual pin reset, and check no early fetch or RAM write. Exercise
both straps, a strap change after sampling, reset during a partial load
and first fetch after the final write. Model flash output enable through
deselection, test GPIO/console ownership and verify the external clock
switch produces no runt or extra pulses. Power-ramp and shortest-period
evidence requires extracted simulation and STA. The MCU has no measured
frequency, UART accuracy or independent on-chip reset specification yet.

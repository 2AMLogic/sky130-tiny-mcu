bit-serial RISC-V implementation by pinned reference rather than writing a
new one. The README draft named no core. Facts below were read from the

A GitHub repository search for "bit-serial risc-v" (2026-11-19) surfaces
olofk/serv as the only dedicated, standalone, maintained bit-serial RISC-V
CPU project; the remaining hits are collections or educational repositories,
not integration-ready cores with a compliance CI. No second candidate was
found to compare against at the same level of evidence.

**Draft-value corrections found while verifying** (access 2026-11-19):

- The draft row says "RV32E base integer". SERV's datasheet at the pin says
  **RV32IZifencei**, with 32 architectural integer registers (x0–x31),
  and `serv.core` exposes no RV32E parameter (register addresses are `5 + WITH_CSR` bits).
  The "RV32E" figure was general knowledge about older SERV versions and is
  stale at the pinned commit. The draft's RV32I "stretch" is in fact what
  the pinned core implements as its base.
- The draft table lists no interrupt stance. The pinned core offers exactly
  one interrupt line (timer) plus machine traps; anything else would be
  local RTL, which this repo does not allow (pinned reference, unmodified).

## Decision

1. **Core: SERV**, wrapped by upstream `servile` (which instantiates
   `serv_top`) with its external RF port set to 8 bits (record 0002), taken
   **by pinned reference, unmodified**: pinned upstream commit
   **`f200eb2ed7b69ac1c6b8eddd47654522aeee5ce8`** (olofk/serv main,
   2026-08-25, version 1.4.0). The pin is fetched by a script into the build
   tree, never hand-copied into `rtl/`; any local change requires a new
   decision record that supersedes this one. Mechanism mirrors the sibling
   repo's pinned-core fetch (`scripts/fetch-cve2.sh` in
   2AMLogic/sky130-riscv-soc @ `e1135913b57ebf0cd57a7882772545fedb7291d0`,
   read 2026-11-19).
2. **ISA configuration: RV32IZifencei with the CSR subset SERV ships**
   (`WITH_CSR=1`), `COMPRESSED=0`, `MDU=0`, datapath `W=1`. `WITH_CSR=1`
   is required for the timer interrupt line and machine traps; the exact
   CSR subset is whatever the pinned `serv_csr.v` implements, and is
   enumerated by the RTL issue from the source, not relaxed here.
3. **License: ISC** (permissive). Compatible with this repo's Apache-2.0:
   both grant use/modification/redistribution; ISC requires preservation of
   the copyright notice, satisfied by keeping SERV's source headers and
   LICENSE with the pinned checkout. The Servile wrapper and shared-memory
   adapter carry Apache-2.0 headers. Preserve those notices as well.
4. **Interrupts: exactly one timer-IRQ line** into `i_timer_irq`, plus
   machine traps. No external interrupt lines, no interrupt controller.
5. **Core supply: 1.8 V** — the nominal core voltage of the
   `sky130_fd_sc_hd` cells this repo synthesizes with (PDK liberty corner
   `tt_025C_1v80`; see record 0006 for the corner set). No decision to
   make; the row exists so the table is complete.

## Alternatives considered

- **Writing a new bit-serial core.** Rejected — the repo instructions
  forbid it absent a decision record justifying it; none exists.
- **QERV (`W=4` datapath)**. Rejected for the target: ~4× the datapath
  activity for a speed this block does not need. Remains the stretch.
- **C extension (`COMPRESSED=1`).** Rejected for the target: decoder area
  against a 0.10 mm² budget whose largest single consumer is the RAM
  (record 0002). Code density matters for the 112 B program/data region (see
  0003), so it remains the stretch, taken only with an area measurement.
- **M extension (external MDU per `MDU=1`).** Rejected: adds an external
  multiplier/divider block this block's control tasks do not need.
- **RV32E.** Not offered by the pinned core at all (no parameter, 5-bit
  register addresses); the draft's RV32E row is dropped as stale, not
  relaxed.
- **Ibex / CVE2 (the sibling repo's cores).** Rejected: pipelined
  full-datapath cores, not bit-serial; they are the right choice for a
  frequency-claim canary (sky130-riscv-soc) and the wrong one for an
  area-claim one.

## Consequences

- Performance is bounded by the bit-serial datapath (order 10² cycles per
  instruction at `W=1`). The block targets control tasks at ≥ 16 MHz
  nominal (record 0005 fixes the clock source). No MIPS claim is made here.
- The register file lives in the shared RAM (Servile arrangement), which
  couples this record to record 0002 (memory) and consumes RAM cycles for
  register access.
- SERV's own sky130/OpenLANE precedent means the pinned tree is known to
  reach the sky130 standard-cell flow, but this repo synthesizes with its
  own Yosys/OpenROAD flow; the first synthesis run re-measures SERV's area
  in this repo's flow (record 0006).
- Defects found in the pinned SERV tree are filed upstream at olofk/serv,
  not patched locally.
